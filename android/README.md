# One Day for Android (Google Play)

The Play app is the website itself: a [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity) that opens https://getone.day full screen in the phone's Chrome. There is no app code. Each change to the site reaches the app at once, sync with Google Drive, Dropbox or OneDrive works as in Chrome, and the tasks are the ones Chrome already holds for getone.day on that phone, since the app uses Chrome's own storage.

## How it works

- **Package** `com.bemorin.oneday` (the same name as the Apple app's bundle ID), app name One Day.
- **The start address carries a mark**, `https://getone.day/?app=android`. The page reads it (`PLAY` in [`public/app.js`](../public/app.js)), keeps it in `sessionStorage` (`oneday.app`) for as long as the app's tab lives, and takes it out of the address at once, so a day sent from the app never carries it. Chrome also names the app as the page's referrer (`android-app://com.bemorin.oneday/`), which is all a link opened in the app shows.
- **In the app, the coffee is left out.** The footer's "Buy me a ☕" goes to Ko-fi, a payment outside Google Play's billing, so the page drops it in the app (and so More, search's foot and the guide, which copy or repeat it, drop it too). One Day stays free, and the website keeps Ko-fi. The app never offers to install One Day either: it is installed.
- **Full screen, no address bar**, because the site vouches for the app: [`public/.well-known/assetlinks.json`](../public/.well-known/assetlinks.json) (Digital Asset Links) names the package and the SHA-256 fingerprints of the keys allowed to sign it: the upload key, and Google's app signing key once Play App Signing shows it (Play Console, the app's **App signing** page). Without it, the app still opens, with a browser bar on top.
- **Signing.** Play App Signing: Google keeps the key that signs what users install; the upload key only proves an upload comes from us. The upload key is never in this repository. It lives in the maintainer's password manager (a zip with the keystore and its password).
- **Only Chrome's storage, never a WebView.** If no browser on the phone can host a Trusted Web Activity, the app opens a Custom Tab (`fallbackType: customtabs`). A WebView would have storage of its own, and Google refuses its sign-in page there. If the phone's default browser hosts Trusted Web Activities itself (Samsung Internet, for example), the app opens in it, with that browser's tasks.
- No permissions, no notifications (`enableNotifications: false`), nothing collected.

## Layout

| Path | What it is |
| --- | --- |
| `twa-manifest.json` | Bubblewrap's description of the app: package, start address, colours, icons, version, signing key alias and fingerprints |
| everything else | Generated by Bubblewrap from `twa-manifest.json`, and not kept in git |

## Building

Needs Node, [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) (`npm i -g @bubblewrap/cli`), a JDK 17 and the Android SDK (Bubblewrap's `~/.bubblewrap/config.json` says where they are).

1. Put the upload key where `signingKey.path` says (`../../../android/key/one-day-upload.keystore`, beside the repository's checkout), or pass `--signingKeyPath`.
2. In this folder: `bubblewrap update` (raises the version code and name; `--skipVersionUpgrade` to keep them), then `bubblewrap build --skipPwaValidation`, with the key's password in `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD`.
3. Upload `app-release-bundle.aab` to Play Console. Every upload needs a version code above the last one: commit `twa-manifest.json` after each `update`.

`bubblewrap build` runs `gradlew.bat` from this folder, which a shell that won't run programs from the current folder (`NoDefaultCurrentDirectoryInExePath`) refuses. There, do its steps by hand, with full paths: `gradlew.bat bundleRelease`, then `jarsigner -sigalg SHA256withRSA -digestalg SHA-256 -keystore <upload keystore> -signedjar app-release-bundle.aab app/build/outputs/bundle/release/app-release.aab upload`. The app needs Android 7.0 or later (`minSdkVersion` 24, what Android Browser Helper asks).

A new build is needed only to change the app itself: its name, icon, colours, start address, or the Android version it targets (Google Play raises the required target every year). Changes to the site need no build.
